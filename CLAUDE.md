# Personal website — CLAUDE.md

Static personal site and blog built with [Eleventy](https://www.11ty.dev/) (v3). Posts are written in org-mode. The site language is **Spanish**.

## Git workflow — read this first

This project is worked on from several machines and is only kept in sync manually through git. There must be exactly **one** authoritative version, the one on `main` at the remote. So:

**Before making any change**, check that the local repository is up to date:

```bash
git status          # is the working tree clean? are we on main?
git fetch origin
git status -sb      # behind origin/main? then pull before touching anything
git pull --rebase   # if behind
```

If the working tree already has uncommitted changes, or the branch has diverged from `origin/main`, stop and ask before proceeding — don't build new work on top of an unclear state.

**After making any change**, commit it and push it:

```bash
git add <files>
git commit -m "mensaje breve"
git push
```

Don't leave finished work uncommitted or unpushed at the end of a task. A push to `main` also triggers the GitHub Pages deploy (see [Deployment](#deployment)), so pushing is what actually publishes the change.

## Writing a post

Create a `.org` file in `src/posts/`. Metadata comes from org keywords at the top:

```org
#+TITLE: El título de la entrada
#+DATE: 2026-05-01
#+FILETAGS: :etiqueta-uno:etiqueta-dos:

Contenido aquí.
```

- `#+FILETAGS:` uses the `:tag:` colon-delimited format.
- The URL of the post is derived from the filename: `mi-entrada.org` → `/weblog/mi-entrada/`.
- Posts are sorted newest-first automatically.

## Adding a book to the reading log

Create a `.org` file in `src/libros/`. It always adds a row to the table at `/lecturas/`:

```org
#+TITLE: Lonesome Dove
#+AUTOR: Larry McMurtry
#+DATE: 2026-04-30
#+ENLACE: /weblog/mi-entrada/    ← optional

Comentario opcional sobre el libro.
```

`#+DATE:` is the date the book was finished; the table sorts newest-first automatically. What the title links to depends on the file:

| File contains | Title in the table links to |
|---|---|
| `#+ENLACE:` | that URL (an off-site link also gets a `↗` mark) |
| a body, no `#+ENLACE:` | a generated page at `/lecturas/<slug>/` |
| neither | nothing — plain text |

`#+ENLACE:` wins over a body. Arbitrary org keywords like `#+AUTOR:` and `#+ENLACE:` work because the plugin runs `uniorg-extract-keywords`, which puts every keyword on `item.data` lowercased (`item.data.autor`, `item.data.enlace`).

## How the org plugin works

`eleventy-plugin-org` is **not** a standard Eleventy template engine. It reads `.org` files from a directory (`orgDir`), converts them to HTML, and exposes collections. It is registered three times in `.eleventy.js`:

- `src/posts/` → `collections.org` (blog posts) and `collections.orgTags` — array of `{ tagName, posts[] }`, one entry per tag
- `src/pages/` → `collections.orgPages` (standalone pages)
- `src/libros/` → `collections.orgLibros` (reading log)

Each item has `{ data.slug, title, date, tags, content }`, plus any other org keyword on `data`. Post pages are generated by `src/weblog/post.njk` using Eleventy pagination over `collections.org` (one page per item). Tag pages work the same way via `etiquetas.njk` over `collections.orgTags`, standalone pages via `src/paginas/pagina.njk` over `collections.orgPages`, and book pages via `src/lecturas/libro.njk` over `collections.orgLibros` — that one filters the collection with `pagination.before` in `libro.11tydata.js`, so books without a commentary generate no page.

**Important:** post metadata lives at `post.data.slug`, `post.title`, `post.date`, `post.tags`, `post.content` — not as standard Eleventy front matter.

## Custom filters (`.eleventy.js`)

| Filter | Usage | Purpose |
|---|---|---|
| `head` | `collection \| head(n)` | First N items of an array |
| `isoDate` | `date \| isoDate` | Formats a date as `YYYY-MM-DD` |
| `spanishDate` | `date \| spanishDate` | Formats a date as `D de mes de AAAA` |
| `stripLeadingSlash` | `post.data.slug \| stripLeadingSlash` | Removes the leading `/` from slugs for building URLs |
| `demoteHeadings` | `content \| demoteHeadings` | Rewrites `h1` → `h2` in org content so body headings sit below the page title |
| `localizeFootnotes` | `content \| localizeFootnotes` | Renames the org plugin's "Footnotes:" heading to Spanish |
| `fixFootnoteLinks` | `content \| fixFootnoteLinks` | Rewrites footnote hrefs to same-page anchors (the plugin emits slug-based URLs that 404) |

The RSS plugin (`@11ty/eleventy-plugin-rss`) also adds `dateToRfc3339` and `getNewestCollectionItemDate`.

## Styles and dark mode

All styles are in `src/assets/style.css`. Design tokens are CSS custom properties on `:root` (light) and `[data-theme="dark"]`. No JavaScript build step — the CSS is copied as-is.

The dark-mode toggle button in `base.njk` sets `data-theme` on `<html>` and persists the choice in `localStorage`. A small inline `<script>` in `<head>` applies the saved theme before paint to avoid flash.

## Deployment

Push to `main` → GitHub Actions builds the site and deploys `_site/` to GitHub Pages via the official Pages actions. Requires **Settings → Pages → Source: GitHub Actions** to be enabled in the repo.

Update `url` in `src/_data/site.js` to match the actual GitHub Pages URL before first deploy.
